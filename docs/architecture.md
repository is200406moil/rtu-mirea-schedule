# Архитектура

## Обновление расписания

`POST /api/refresh` запускает корутину обновления и сразу отвечает `202 Accepted`. Повторный запуск во время активного обновления возвращает `409 Conflict`.

Служебный endpoint защищён заголовком `X-Refresh-Key`. Ключ не передаётся в URL, поэтому не попадает в обычные access-логи и историю браузера.

Обновление проходит в четыре шага:

1. Поиск групп через публичный endpoint `schedule-of`.
2. Загрузка iCalendar для каждой группы.
3. Разбор событий и группировка занятий по дню и времени.
4. Запись нормализованного расписания в MongoDB через `replace_one(..., upsert=True)`.

HTTP-запросы имеют timeout и несколько повторных попыток с короткой задержкой. Библиотека Requests синхронная, поэтому вызов переносится через `asyncio.to_thread` и не блокирует event loop.

## Модель хранения

В коллекции `schedule` хранится один документ на группу:

```json
{
  "group": "ИКБО-14-23",
  "schedule": {
    "monday": {"lessons": []},
    "tuesday": {"lessons": []}
  }
}
```

Внутри дня занятия сгруппированы по временному слоту. Один слот может содержать несколько занятий, например для разных подгрупп.

## Границы ответственности

- `app/schedule_parser` — получение и преобразование внешних данных;
- `app/crud` — MongoDB-запросы;
- `app/api` — HTTP-контракт и коды ответа;
- `app/models` — Pydantic-модели расписания;
- `app/core` — конфигурация и расчёт учебной недели.

## Почему MongoDB

Расписание читается в основном целиком по группе и имеет вложенную структуру «день → временной слот → занятия». Документная модель позволяет сохранить этот объект без дополнительных таблиц и сборки ответа через несколько JOIN.

Цена решения — более сложный поиск по вложенным полям преподавателя и аудитории. Для высокой нагрузки потребовались бы отдельные поисковые представления или индексы.

## Что потребовалось бы для production

- вынести фоновые задания и их статус в очередь задач;
- ограничить параллелизм загрузки и добавить метрики;
- хранить время последнего успешного обновления;
- добавить интеграционные тесты с MongoDB;
- настроить явный список разрешённых CORS origins.
